# Temas do painel — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cinco temas selecionáveis (Clássico, Papel, Painel, Terminal, Mission Control), cada um com light e dark, nos três hosts da webview. O Clássico continua padrão e fica pixel a pixel igual ao painel de hoje.

**Architecture:** Uma camada de tokens semânticos `--ct-*` passa a ser a única fonte de cor dos componentes. O Clássico é o `:root` padrão, que mapeia os tokens para `--vscode-*`. Cada outro tema é um arquivo CSS que só redefine tokens em `:root[data-ct-theme][data-ct-mode]`. A webview detecta o modo (light, dark ou hc) do mesmo jeito nos três hosts e aplica os dois atributos no `<html>`. O host guarda a escolha (setting no VS Code, `PropertiesComponent` no JetBrains) e a manda como `{ type: 'appearance' }`. O que CSS não resolve vira um de quatro `ThemeTraits`, e cada traço entra só na fase do tema que o usa.

**Tech Stack:** TypeScript, Svelte 5 (webview), vitest (Node), Playwright + Chromium (screenshots de regressão, só dev), Kotlin + JUnit (plugin JetBrains).

**Spec:** `docs/specs/2026-11-02-temas-design.md`

## Global Constraints

- **Ids dos temas:** `classic`, `papel`, `painel`, `terminal`, `mission`, nessa ordem em todos os lugares (registro, enum do `package.json`, QuickPick, lista Kotlin). Cada fase acrescenta só os seus ids: v0.21.0 = `classic`, `papel`; v0.22.0 + `painel`, `terminal`; v0.23.0 + `mission`.
- **Padrão `classic`.** Valor ausente ou desconhecido vira `classic`, em todos os hosts.
- **Componentes não usam `var(--vscode-*)`.** Só `var(--ct-*)`, `var(--sp-*)`, `var(--radius)` e vars locais declaradas no próprio arquivo (como `--tone`). `--vscode-*` só aparece em `src/webview/themes/tokens.css` e em `src/webview/themes/painel.css`. Trava: `tests/webview/themeTokens.test.ts`.
- **Arquivo de tema só declara custom properties.** Seletores permitidos: `:root[data-ct-theme="<id>"]` e `:root[data-ct-theme="<id>"][data-ct-mode="dark|light"]`. Propriedades permitidas: `--ct-*`, `--sp-1..3`, `--radius`. Nada de seletor de componente: o hash de escopo do Svelte tornaria a cascata dependente da ordem do bundle. Trava: o mesmo teste.
- **Fundo, cor de texto e fonte do tema entram por `.ct-root`** (a classe do `<main>` do `App.svelte`), numa única regra em `tokens.css` que exclui o Clássico. Nunca em `body`: o VS Code injeta `body { color: var(--vscode-editor-foreground); font-family: … }` em toda webview, e o site tem `.landing` com cor e tipografia próprias. Trava: o runner de screenshots compara a cor e a fonte computadas do `<main>` com `--ct-fg` e `--ct-font` nos temas que não são o Clássico.
- **Temas com paleta própria (`papel`, `terminal`, `mission`) usam só hex de 6 dígitos** nos blocos de modo, e passam no teste de contraste (`tests/webview/themeContrast.test.ts`): `fg/bg ≥ 7`, `muted/bg ≥ 4.5`, `link/bg ≥ 4.5`, `run`, `ok`, `done`, `warn`, `danger`, `accent` sobre `bg ≥ 3`. Se houver `--ct-bg-alt` (faixa), os mesmos pisos valem sobre ele. Par falhou: muda a cor, nunca o piso. O mesmo teste exige que eles redefinam todo token que, no Clássico, vem direto de `--vscode-*` (fora as fontes). Token novo em `tokens.css` deriva de outro `--ct-*` sempre que der (como `--ct-track: var(--ct-border)`), e aí acompanha os temas sozinho.
- **High contrast usa sempre o Clássico** (`effectiveTheme(x, 'hc') === 'classic'`), sem alterar a escolha salva.
- **Nenhum tema esconde informação.** Faixa de agentes e medidores são *adicionais*. Árvore, todos, tabela de uso, perguntas pendentes e uso do projeto continuam em todos os temas.
- **Regressão visual por imagem, em todos os temas.** `npm run shots` grava em `shots/baseline/` só as imagens que faltam: antes da Task 4 é o Clássico do código atual, e cada tema grava as suas na task que cria o `.css` dele. Depois de cada task que toca CSS ou componentes, `npm run shots -- --compare` precisa passar em todos os temas que já existem (o Clássico e um por arquivo em `src/webview/themes/`). O Clássico não muda nunca. Outro tema só muda de propósito, com `npm run shots -- --update --themes <id>` e o motivo no commit. `shots/` e `dist-shots/` ficam fora do git e do VSIX. O baseline é local, porque depende da máquina e do Chromium que o gravaram: num worktree novo, gere tudo a partir de um commit verde antes de mexer em qualquer coisa. Screenshot para README ou conferência sai sempre com `--compare`, que grava em `shots/current/`.
- **CSP da webview:** sem fontes nem imagens externas. Fonte mono = `--vscode-editor-font-family` (no JetBrains, o `ThemeShim` já a define).
- **i18n:** toda chave nova entra nos cinco idiomas de `src/i18n/messages.ts` (`en`, `pt-br`, `es`, `zh-cn`, `zh-tw`). Textos nativos do JetBrains em `NotifyMessages.kt`, copiados verbatim. Títulos de comando e descrições de setting nos cinco `package.nls*.json` (em `zh-cn` e `zh-tw`, em inglês, como os atuais). Os testes de paridade (`tests/i18n/messages.test.ts`, `tests/i18n/packageNls.test.ts`, `NotifyMessagesTest.kt`) quebram se faltar um idioma.
- **Comandos de verificação:** `npm run typecheck`, `npm run check:svelte`, `npm test`, `npm run build`. Um arquivo: `npx vitest run <caminho>`. JetBrains, a partir de `jetbrains/` e com `npm run build` feito antes: `cmd //c "<raiz do repo, caminho absoluto>\jetbrains\gradlew.bat" test --console=plain`.
- **Commits:** um por tarefa, título em pt-BR **sem acentos**, com prefixo convencional (`feat`, `fix`, `test`, `docs`, `build`, `refactor`), terminando com:

## Review Focus

1. **O Clássico não pode mudar nenhum pixel.** A migração das 94 referências a `--vscode-*` troca a expressão, não o valor. Os `var(--vscode-x, fallback)` levam o fallback para dentro do token. Prova: `npm run shots -- --compare` na Task 4, passo 7. Fora da prova: hover, foco e o que só o JetBrains tem de diferente do `theme.css` (por exemplo, a falta de `--vscode-textLink-foreground` no `ThemeShim`). Nesses casos, confira no olho os fallbacks de `tokens.css`.
2. **Texto herdado fora do Clássico:** no VS Code e no site, o `:root` não chega ao texto herdado. A regra `.ct-root` resolve; o runner trava isso. Conferir à mão no VS Code real (Task 10, passo 1).
3. **Modo no JetBrains:** sem classe no `body`, o modo vem da luminância de `--vscode-foreground`, com limiar 0,18. Os testes da Task 3 cobrem hex de 3 e 6 dígitos e `rgb()`. Conferir à mão no IDE (Task 9, passo 9), trocando de Darcula para Light *com o painel aberto*: o `updateThemeVars` muda o `style` do `<html>`, e o observer precisa reagir.
4. **Prévia do QuickPick no VS Code:** cancelar (Esc ou clique fora) volta ao tema salvo, e aceitar grava em `Global`. Teste manual na Task 10, passo 1.
5. **Site:** `App.svelte` é montado sem `main.ts`. Os temas entram via `@import` em `app.css`, e o modo via `<html data-theme>`. `tests/site/cssTokens.test.ts` precisa continuar verde. A landing não muda de tema: `.landing` tem especificidade maior que o `:root`, e ela não usa `--sp-*` nem `--radius`.
6. **Variantes de componente com o Clássico intacto:** `Meter.svelte` (Task 13) e o `StatusIcon` em texto (Task 12) precisam gerar, no Clássico, o mesmo DOM e o mesmo CSS de antes. Prova: screenshots, inclusive os casos `full` e `alert`, que têm as linhas de limite.
7. **`--update` em revisão:** nenhuma task deste plano muda o visual de um tema que já existe. Se uma task precisou de `--update`, confira o motivo no commit e abra as imagens: pode ser regressão sendo aceita.

`scripts/themeShots/cases.ts`. Sem DOM: é importado pela página e pelo runner. O frame real da demo não tem perguntas pendentes, limites, rodapé da ponte nem estados vazios, e só mostra contexto `ok` e cache `good`. Os casos sintéticos cobrem o resto:

```ts
// Estados do painel que o harness fotografa. Sem DOM: usado pela pagina
// (entry.ts) e pelo runner (run.mts).
import type { AgentTodos, ProjectUsage, SessionSnapshot } from '../../src/types';

export interface ShotScript {
  frames: { atMs: number; snapshot: SessionSnapshot }[];
  projectUsage: ProjectUsage;
}

export const SHOT_CASES = ['live', 'full', 'alert', 'project', 'empty', 'awaiting', 'taskToolsOff', 'error'] as const;
export type ShotCase = (typeof SHOT_CASES)[number];

// O frame mais tardio com uma task em andamento: cobre os tres status.
function pickFrame(script: ShotScript): ShotScript['frames'][number] {
  const withWork = [...script.frames].reverse().find((f) =>
    f.snapshot.agents.some((a) => a.todos.some((t) => t.status === 'in_progress')),
  );
  return withWork ?? script.frames[script.frames.length - 1];
}

// Instante congelado: 30s depois do carimbo mais novo do frame. Nao usar
// recordedAt: a gravacao reproduziu um transcript antigo, 14 dias antes dele,
// e a task em andamento apareceria com 333h nos prints.
export function shotTime(script: ShotScript): number {
  const stamps = pickFrame(script).snapshot.agents.flatMap((a) =>
    a.todos.flatMap((t) => [t.startedAt ?? 0, t.completedAt ?? 0]),
  );
  return Math.max(...stamps) + 30_000;
}

function isoAfter(t: number, hours: number): string {
  return new Date(t + hours * 3_600_000).toISOString();
}

export function caseSnapshot(c: ShotCase, script: ShotScript): SessionSnapshot | null {
  const base = pickFrame(script).snapshot;
  const t = shotTime(script);
  switch (c) {
    case 'live':
    case 'project':
      return base;
    case 'empty':
    case 'error':
      return null;
    case 'awaiting':
      return { ...base, agents: [], usage: undefined };
    case 'taskToolsOff':
      return { ...base, agents: [], usage: undefined, taskToolsOff: true };
    case 'full': {
      // Tons de tipo de agente, sub-agent rodando, lista defasada e historico.
      const [main, a, b, c2] = base.agents;
      const agents: AgentTodos[] = [
        { ...main, todosUpdatedAt: t - 600_000 },
        { ...a, agentType: 'Explore', status: 'running' },
        { ...b, agentType: 'Plan' },
        { ...c2, agentType: 'revisor-custom' },
        { ...c2, agentId: 'shot-historico', name: 'historico', todos: [], status: 'completed' },
      ];
      return {
        ...base,
        agents,
        bridge: 'active',
        pendingQuestions: [
          { kind: 'question', header: 'Deploy', text: 'Publicar agora ou esperar a revisao?', line: 10 },
          { kind: 'plan', text: 'Migrar os tokens em duas etapas', line: 20 },
        ],
        usage: {
          ...base.usage!,
          context: { tokens: 130_000, limit: 200_000, source: 'mod' },
          cache: { input: 30, read: 60, creation: 10 },
          rateLimits: {
            readAt: t,
            limits: [
              { kind: 'five_hour', percentUsed: 42, resetsAt: isoAfter(t, 3) },
              { kind: 'seven_day', percentUsed: 71, resetsAt: isoAfter(t, 72) },
              { kind: 'spend_limit', percentUsed: 93, resetsAt: isoAfter(t, 240) },
            ],
          },
        },
      };
    }
    case 'alert':
      return {
        ...base,
        bridge: 'off',
        usage: {
          ...base.usage!,
          context: { tokens: 190_000, limit: 200_000 },
          cache: { input: 80, read: 10, creation: 10 },
        },
      };
  }
}
```

`scripts/themeShots/entry.ts`. Ele injeta uma bridge de fixture antes de montar o app, como a demo do site faz com `window.__claudeTodosDemo`:

```ts
// Harness de screenshots: monta a webview REAL com uma bridge de fixture.
// Parametros pela URL: ?mode=dark|light&theme=<id>&case=<caso>
// A bridge responde ao `ready` com locale, appearance (quando o host ja
// suporta) e o snapshot do caso.
import script from '../../site/src/demo/scripts/smoke-test.json';
// Mesma ordem do site (LandingLayout.astro): app.css antes de theme.css.
import '../../src/webview/app.css';
import '../../site/src/demo/theme.css';
import type { WebviewBridge } from '../../src/webview/bridge';
import type { ExtensionMessage } from '../../src/types';
import { caseSnapshot, type ShotCase, type ShotScript } from './cases';

const params = new URLSearchParams(location.search);
const mode = params.get('mode') === 'light' ? 'light' : 'dark';
const theme = params.get('theme') ?? 'classic';
const shotCase = (params.get('case') ?? 'live') as ShotCase;
const shot = script as unknown as ShotScript;

// Simula os dois sinais de modo: a classe que o VS Code poe no body e o
// data-theme que o theme.css do site usa para trocar as --vscode-*.
document.documentElement.dataset.theme = mode;
document.body.classList.add(mode === 'light' ? 'vscode-light' : 'vscode-dark');

let handler: ((m: ExtensionMessage) => void) | null = null;
const send = (m: ExtensionMessage) => handler?.(m);
const bridge: WebviewBridge = {
  onMessage(h) { handler = h; },
  post(msg) {
    if (msg.type === 'projectUsage') {
      send({ type: 'projectUsage', usage: shot.projectUsage });
      return;
    }
    if (msg.type !== 'ready') return;
    send({ type: 'locale', locale: 'pt-br' });
    // Antes da Task 5 a mensagem 'appearance' nao existe: o store ignora.
    send({ type: 'appearance', theme } as unknown as ExtensionMessage);
    if (shotCase === 'error') send({ type: 'error', message: 'sidecar terminated' });
    else send({ type: 'snapshot', snapshot: caseSnapshot(shotCase, shot) });
  },
};
(window as unknown as { __claudeTodosDemo: WebviewBridge }).__claudeTodosDemo = bridge;

await import('../../src/webview/main');
document.body.dataset.ready = '1';
```

```ts
// Uso:
//   npm run shots                -> grava em shots/baseline/ so os <tema>-<caso>-<modo>.png que faltam
//   npm run shots -- --compare   -> grava shots/current/ e compara com o baseline
//   npm run shots -- --update --themes papel -> regrava o baseline de um tema (mudanca intencional)
//   Filtros: --themes classic,papel --cases live,full
// Sem --themes: o Classico e um tema por arquivo de src/webview/themes/. Tema
// registrado que ainda nao tem .css fica de fora ate a task que o cria.
// Compara byte a byte (mesma maquina, mesmo Chromium => PNG deterministico).
// Diferenca: lista os arquivos e sai com codigo 1; abrir os dois PNGs lado a lado.
import { chromium } from 'playwright';
import { execSync } from 'node:child_process';
import * as fs from 'node:fs';
import * as path from 'node:path';
import { pathToFileURL } from 'node:url';
import { SHOT_CASES, shotTime, type ShotScript } from './cases.ts';

const ROOT = path.resolve(import.meta.dirname, '../..');
const args = process.argv.slice(2);
const compare = args.includes('--compare');
const update = args.includes('--update');
const listArg = (flag: string, fallback: readonly string[]): readonly string[] =>
  args.includes(flag) ? args[args.indexOf(flag) + 1].split(',') : fallback;
const themesDir = path.join(ROOT, 'src/webview/themes');
const themeFiles = fs.existsSync(themesDir)
  ? fs.readdirSync(themesDir).filter((f) => f.endsWith('.css') && !['tokens.css', 'index.css'].includes(f)).map((f) => f.replace(/\.css$/, ''))
  : [];
const themes = listArg('--themes', ['classic', ...themeFiles]);
const cases = listArg('--cases', SHOT_CASES);
const modes = ['dark', 'light'] as const;

// O Classico nao muda nunca. Se um dia mudar de proposito, apague o PNG a mao:
// o proximo `npm run shots` grava o novo.
if (update && themes.includes('classic')) {
  console.error('--update nao aceita o Classico: passe --themes so com os outros temas');
  process.exit(1);
}

execSync('npx vite build --config scripts/themeShots/vite.config.mts --logLevel warn', { cwd: ROOT, stdio: 'inherit' });

// --update grava direto no baseline, como a gravacao das imagens que faltam.
const outDir = path.join(ROOT, 'shots', compare ? 'current' : 'baseline');
fs.mkdirSync(outDir, { recursive: true });
const indexUrl = pathToFileURL(path.join(ROOT, 'dist-shots', 'index.html')).href;
const script = JSON.parse(fs.readFileSync(path.join(ROOT, 'site/src/demo/scripts/smoke-test.json'), 'utf8')) as ShotScript;

// file:// bloqueia modulos ES por CORS sem esta flag. Ela evita subir um
// servidor, que no Windows costuma deixar processo orfao segurando a porta.
const browser = await chromium.launch({ args: ['--allow-file-access-from-files'] });
const context = await browser.newContext({ viewport: { width: 360, height: 1800 }, reducedMotion: 'reduce', deviceScaleFactor: 2 });
// Antes do goto: clock.svelte.ts le Date.now() no load do modulo.
await context.clock.setFixedTime(shotTime(script));
const failures: string[] = [];
for (const theme of themes) {
  for (const shotCase of cases) {
    for (const mode of modes) {
      const file = `${theme}-${shotCase}-${mode}.png`;
      const base = path.join(ROOT, 'shots', 'baseline', file);
      if (!compare && !update && fs.existsSync(base)) continue;
      const page = await context.newPage();
      await page.goto(`${indexUrl}?mode=${mode}&theme=${theme}&case=${shotCase}`);
      await page.waitForSelector('body[data-ready="1"] main');
      await page.waitForFunction(() => !document.querySelector('main .loading'));
      if (shotCase === 'project') await page.locator('main .project .header').click();
      await page.evaluate(() => document.fonts.ready);
      // transition:slide usa a Web Animations API, que o reducedMotion nao zera.
      await page.waitForTimeout(400);
      // O spinner do StatusIcon e SMIL (animateTransform): nem o reducedMotion
      // nem o relogio congelado o param, e o angulo mudaria a cada imagem.
      await page.evaluate(() => {
        document.querySelectorAll('svg').forEach((s) => { s.pauseAnimations(); s.setCurrentTime(0); });
      });
      await page.locator('main').screenshot({ path: path.join(outDir, file) });
      if (theme !== 'classic') {
        // Regra .ct-root: o texto herdado precisa usar a cor e a fonte do tema.
        const inherited = await page.evaluate(() => {
          const probe = document.createElement('span');
          probe.style.cssText = 'color: var(--ct-fg); font-family: var(--ct-font)';
          document.documentElement.append(probe);
          const m = getComputedStyle(document.querySelector('main')!);
          const p = getComputedStyle(probe);
          const same = m.color === p.color && m.fontFamily === p.fontFamily;
          probe.remove();
          return same;
        });
        if (!inherited) failures.push(`${file}: texto herdado nao usa --ct-fg/--ct-font`);
      }
      await page.close();
      if (compare) {
```

```ts
// Modo de cor do painel, detectado do mesmo jeito nos tres hosts:
//  - VS Code: classe que ele poe no <body> (vscode-light/-dark/-high-contrast*)
//  - site: <html data-theme> (ThemeToggle + theme.css)
//  - JetBrains: nenhum dos dois; o ThemeShim injeta --vscode-foreground, e
//    texto claro implica fundo escuro.
import { effectiveTheme, type ColorMode, type UiThemeId } from '../../themes';

// Ponto em que o contraste com branco e com preto se iguala: acima dele, o
// texto so e legivel sobre fundo escuro. Nao usar 0,5: o #bbbbbb do Darcula
// tem luminancia 0,497.
const LIGHT_TEXT_LUMINANCE = 0.18;

export interface ModeInput {
  bodyClasses: readonly string[];
  dataTheme: string | null | undefined;
  foreground: string;
}

export function relativeLuminance(color: string): number | null {
  const c = color.trim();
  let rgb: number[] | null = null;
  const hex = /^#([0-9a-f]{3}|[0-9a-f]{6})$/i.exec(c);
  if (hex) {
    const h = hex[1].length === 3 ? [...hex[1]].map((x) => x + x).join('') : hex[1];
    rgb = [0, 2, 4].map((i) => parseInt(h.slice(i, i + 2), 16));
  } else {
    const m = /^rgba?\(\s*(\d+)\s*,\s*(\d+)\s*,\s*(\d+)/i.exec(c);
    if (m) rgb = [m[1], m[2], m[3]].map(Number);
  }
  if (!rgb) return null;
  const [r, g, b] = rgb.map((v) => {
    const s = v / 255;
    return s <= 0.03928 ? s / 12.92 : ((s + 0.055) / 1.055) ** 2.4;
  });
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
}

export function resolveMode(i: ModeInput): ColorMode {
  const c = i.bodyClasses;
  if (c.includes('vscode-high-contrast') || c.includes('vscode-high-contrast-light')) return 'hc';
  if (c.includes('vscode-light')) return 'light';
  if (c.includes('vscode-dark')) return 'dark';
  if (i.dataTheme === 'light' || i.dataTheme === 'dark') return i.dataTheme;
  const l = relativeLuminance(i.foreground);
  if (l === null) return 'dark';
  return l > LIGHT_TEXT_LUMINANCE ? 'dark' : 'light';
}

export function applyAppearance(
  el: { dataset: Record<string, string | undefined> },
  choice: UiThemeId,
  mode: ColorMode,
): void {
  el.dataset.ctTheme = effectiveTheme(choice, mode);
  el.dataset.ctMode = mode;
}

// Le o modo agora e a cada troca de tema do editor. Devolve o desligamento.
export function observeMode(doc: Document, onChange: (mode: ColorMode) => void): () => void {
  const read = (): ColorMode =>
    resolveMode({
      bodyClasses: [...doc.body.classList],
      dataTheme: doc.documentElement.dataset.theme,
      foreground: getComputedStyle(doc.documentElement).getPropertyValue('--vscode-foreground'),
    });
  let last = read();
  onChange(last);
  const obs = new MutationObserver(() => {
    const next = read();
    if (next !== last) { last = next; onChange(next); }
  });
  obs.observe(doc.body, { attributes: true, attributeFilter: ['class'] });
  // style: JetBrains troca as --vscode-* inline (updateThemeVars); data-theme: site.
  obs.observe(doc.documentElement, { attributes: true, attributeFilter: ['style', 'data-theme'] });
  return () => obs.disconnect();
}
```

```kotlin
package com.carlosdealmeida.claudetodos

import com.intellij.ide.util.PropertiesComponent
import com.intellij.openapi.application.ApplicationManager
import com.intellij.util.messages.Topic

/** Espelha src/themes.ts (UI_THEME_IDS). Sincronia travada pelo ThemeChoiceTest. */
object ThemeChoice {
    const val KEY = "claudeTodos.theme"
    const val DEFAULT = "classic"
    val IDS: List<String> = listOf("classic", "papel")

    fun parse(value: String?): String = if (value != null && value in IDS) value else DEFAULT

    fun load(props: PropertiesComponent = PropertiesComponent.getInstance()): String =
        parse(props.getValue(KEY))

    /** Grava e avisa todos os tool windows abertos, de qualquer projeto. */
    fun save(id: String, props: PropertiesComponent = PropertiesComponent.getInstance()) {
        props.setValue(KEY, parse(id), DEFAULT)
        ApplicationManager.getApplication().messageBus
            .syncPublisher(ThemeChoiceListener.TOPIC)
            .themeChanged(parse(id))
    }
}

fun interface ThemeChoiceListener {
    fun themeChanged(id: String)

    companion object {
        val TOPIC: Topic<ThemeChoiceListener> =
            Topic.create("claudeTodos.theme", ThemeChoiceListener::class.java)
    }
}
```

```ts
export function asciiBar(pct: number, width: number): string {
```

```ts
// Comprimento do arco do anel de progresso. Minimo de 4px: um agente sem nada
// concluido ainda precisa de um traco que mostre onde o anel comeca.
export function ringDash(done: number, total: number, circumference: number): number {
  if (total <= 0 || done <= 0) return 4;
  return Math.max(4, Math.min(1, done / total) * circumference);
}
```

Em `format.ts`:

```ts
export interface UsageHeadline {
  ctxPct: number | null;
  models: { model: string; total: number }[];
  cacheRate: number | null;
}

// Mesmas contas da UsageTable (ctxPct com teto 1, cacheRate = read / total).
export function usageHeadline(usage: SessionUsage): UsageHeadline {
  const ctx = usage.context;
  const c = usage.cache;
  const cacheTotal = c ? c.input + c.read + c.creation : 0;
  return {
    ctxPct: ctx ? Math.min(ctx.tokens / ctx.limit, 1) : null,
    models: usage.byModel
      .map((m) => ({ model: m.model, total: m.input + m.output + m.cache }))
      .sort((a, b) => b.total - a.total)
      .slice(0, 2),
    cacheRate: c && cacheTotal > 0 ? c.read / cacheTotal : null,
  };
}

export function todoSegments(todos: Todo[]): ('done' | 'run' | 'pend')[] {
  return todos.map((t) => (t.status === 'completed' ? 'done' : t.status === 'in_progress' ? 'run' : 'pend'));
}
```
